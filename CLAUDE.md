## What This Is

**Note++** — a developer-focused desktop text editor built as an Electron + Monaco clone of Notepad++.  
Located at `D:\NewNotepad`. GitHub: https://github.com/YogeshPraj/Note-

**Target user:** software developers (not generic notepad users).  
**Key differentiators over plain Notepad++:** IntelliSense, integrated terminal, live HTML/Markdown preview with Mermaid diagrams, cloud session sync, Monaco editor engine.

## Architecture Notes

### IPC Pattern
All Node/filesystem access goes through `preload.js`. The renderer calls `window.electronAPI.readFile(path)`, etc. Never use `require()` directly in renderer code.

### Monaco AMD Loader — Critical Loading Order
Monaco's `vs/loader.js` installs a global `define()` function. **marked.umd.js MUST load before `vs/loader.js`**, otherwise marked registers as an AMD module instead of setting `window.marked`, breaking the Markdown preview.

Current script load order in `index.html`:
1. `../node_modules/marked/lib/marked.umd.js`  ← MUST be first
2. `../node_modules/monaco-editor/min/vs/loader.js`
3. xterm, xterm-addon-fit
4. mermaid
5. `renderer.js`

### Monaco Worker URLs
Since `index.html` lives in `src/`, all `node_modules` paths use `../node_modules/`. The Monaco worker inline script in `index.html` uses `${base}../node_modules/monaco-editor/min/`.

In `renderer.js`, the require config uses `'../node_modules/monaco-editor/min/vs'`.

### Preview Panel
- Toggled with `Ctrl+Shift+V` or the 👁 toolbar button
- Only activates for `html` and `markdown` language modes
- Split-pane: editor left, preview right (resizable via drag handle)
- 400ms debounce on keystroke before re-render
- **Markdown preview**: `marked.parse()` with custom `renderer.code` override for Mermaid fences; result injected into `#preview-md-content`
- **Mermaid**: bare Mermaid files (no code fences, starts with `graph`/`flowchart`/etc.) are detected by `isBareRawMermaid()` and rendered directly
- **HTML preview**: rendered in sandboxed `<iframe srcdoc="...">` with mermaid script injected into `<head>`
- **Mermaid Live Editor** (`.mmd` / `.mermaid`): dedicated split-pane editor — Monaco left, live diagram right. Auto-opens preview. Toolbar: templates, SVG/PNG export, zoom controls (Ctrl+scroll too). Error box shows parse failures while preserving last valid diagram. Uses `mermaid.render()` API for direct SVG injection.

### Mermaid (v11) API
```javascript
// For Markdown/HTML preview (run on all .mermaid divs):
mermaid.initialize({ startOnLoad: false, theme: 'default'|'dark', securityLevel: 'loose' });
mermaid.run({ nodes: Array.from(container.querySelectorAll('.mermaid')) });

// For Mermaid Live Editor (direct SVG render):
const { svg, bindFunctions } = await mermaid.render(uniqueId, diagramText);
container.innerHTML = svg;
if (bindFunctions) bindFunctions(container);
```

## Whiteboard Architecture (Excalidraw, Session 7+)

### Component layout
- The whiteboard tab renders an iframe pointing at `src/whiteboard.html`.
- `whiteboard.html` loads `whiteboard.bundle.js` (an esbuild-bundled React app, source: `src/whiteboard-app.jsx`) which mounts `<Excalidraw />` full-viewport.
- Excalidraw's fonts are self-hosted: `build-whiteboard.js` copies `node_modules/@excalidraw/excalidraw/dist/prod/fonts/` into `src/excalidraw-fonts/`, and the bundle sets `window.EXCALIDRAW_ASSET_PATH = './excalidraw-fonts/'` so no CDN call ever happens.
- React / Excalidraw run **only inside the iframe**. The main renderer (`renderer.js`) remains pure JS — no React, no JSX, no bundler.

### Build pipeline
- `npm run build:wb` invokes `build-whiteboard.js`:
  1. Copies fonts → `src/excalidraw-fonts/`
  2. esbuild bundles `whiteboard-app.jsx` → `src/whiteboard.bundle.{js,css}` (IIFE, target Chrome 120, minified, `production` export condition)
  3. Asset files (woff2, etc.) emitted to `src/whiteboard-assets/`
- `npm start` runs `build:wb` then `electron .`
- `npm install` triggers `build:wb` via `postinstall`
- All build artefacts under `src/whiteboard.bundle.*`, `src/whiteboard-assets/`, `src/excalidraw-fonts/` are gitignored

### File Format
Whiteboard files are JSON. Two versions coexist:

**v2 (current — written for all new whiteboards):**
```json
{ "__wb__": true, "version": 2, "source": "excalidraw",
  "elements": [/* Excalidraw scene elements */],
  "appState": { /* slim subset — viewBackgroundColor, scroll, zoom, etc. */ },
  "files":    { /* Excalidraw binary files (images) */ } }
```

**v1 (legacy — still readable, auto-migrated on first edit):**
```json
{ "__wb__": true, "version": 1,
  "elements": [/* old custom-canvas shapes */],
  "idCounter": 5, "camera": { "x": 0, "y": 0, "zoom": 1 } }
```

Detection in `openFile()`: a `.json` / `.whiteboard` / `.excalidraw` file routes to a whiteboard tab if the parsed JSON has `__wb__ === true` OR `type === "excalidraw"` (raw Excalidraw exports). Conversion v1 → v2 happens inside the iframe (`legacyV1ToV2()` in `whiteboard-app.jsx`) when the file is loaded; the next user edit causes the v2 envelope to be written back to disk.

### postMessage Protocol (parent renderer ↔ whiteboard iframe)
_Unchanged from v1 — the iframe still speaks the same wire protocol; only the payload schema inside `content` changed._

| Direction | Message type | Payload |
|---|---|---|
| renderer → wb | `wb-load` | `{ content: string }` — v1 or v2 JSON envelope |
| renderer → wb | `wb-theme` | `{ dark: bool }` |
| renderer → wb | `wb-get-data` | (no payload) — requests current state |
| wb → renderer | `wb-ready` | (no payload) — React mounted + api available |
| wb → renderer | `wb-state` | `{ content: string }` — v2 envelope, debounced 350 ms after each Excalidraw `onChange` |
| wb → renderer | `wb-data` | `{ content: string }` — response to `wb-get-data` |
| wb → renderer | `wb-save-request` | (no payload) — Ctrl+S inside iframe |

### Auto-save Flow
1. User edits in Excalidraw → `onChange(elements, appState, files)` fires
2. `whiteboard-app.jsx` debounces 350 ms → builds v2 envelope → `wb-state` postMessage
3. Dedup guard (`lastSerialized.current`) suppresses no-op states caused by `updateScene` echoes
4. Renderer `wb-state` handler → `tab.content = m.content`, `tab.dirty = true`
5. `scheduleAutoSave()` → 1.5 s → `saveSession()` (session JSON in AppData)
6. `scheduleWbFileSave(tab)` → 1.5 s → `writeFile(tab.filePath, tab.content)` → `tab.dirty = false`

### Storage Paths
- Session (all tabs): `%AppData%\notepp\autosave\session.json`
- New whiteboard backing files: `%AppData%\notepp\Whiteboards\whiteboard-N.json` (v2 envelope)
- User-chosen save path: wherever the user picks via Save As dialog (`.json`, `.excalidraw`, or legacy `.whiteboard`)
