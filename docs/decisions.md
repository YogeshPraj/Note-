# Decisions

One line per decision made without asking. ("Standing decisions" below refers to the restructuring brief of 2026-11-01,
which was not kept in the repository; its outcome is `docs/architecture.md`.)

| Date | Decision | Reason |
|---|---|---|
| 2026-11-01 | Cast lints stay on workspace-wide. Core gets checked conversions in `notepp_core::num` (`try_from`, saturating); the wx workspace gets adapter modules (`ui-kit::px`, `app::platform::{scintilla, wx}`) that alone carry `#![allow(clippy::cast_*)]`. | Standing decision 1; user instruction on 2026-11-01. |
| 2026-11-01 | `notepp_core::num` helpers saturate (negative to 0, overflow to MAX) instead of wrapping. | A wrapped Scintilla position is a silent bug; saturating is safe and testable. |
| 2026-11-01 | Intentional bit truncation (colour channels, hash bytes) is written with masks and `u8::try_from(x & 0xff)`, not `as`. | Keeps the lint strict without changing results. |
| 2026-11-01 | `Result<_, String>` is migrated to `notepp_core::error::Error` (thiserror) in core and `AppError` in the app before the Command registry is built. | Standing decision 2; `execute()` returns typed errors. |
| 2026-11-01 | `cargo clippy --fix` is applied for machine-applicable lints in files being touched. | Standing decision 3. |
| 2026-11-01 | Commands keep their numeric ids; `registry::Command` gives the frequent ones a typed name, and `CommandSpec` rows hold label, palette text, default shortcut and enabled rule. | A 500-variant enum would duplicate the id table; ids are also what menus, sessions and the shortcut mapper store. |
| 2026-11-01 | App-level errors are a hand-written `AppError` (no `anyhow`). | `anyhow` would be a new dependency; `AppError` has three variants and wraps the core's typed `Error`. |
| 2026-11-01 | Commands whose enabled rule says no are ignored silently (no status message) and greyed in the menu and toolbar. | The conventional behaviour. Only Undo, Redo, Cut, Copy, Delete and Reload are gated so far. |
| 2026-11-01 | `ui-kit::num` is a copy of `notepp_core::num`. | The kit may not depend on the core. |
| 2026-11-01 | Toolbar tool-tips come from the registry (name and primary shortcut); a few keep their own text (Print, Encrypt, Passwords, Log Follow). | One place for shortcut text. Tip text of Undo, Redo, Zoom, Word Wrap and Dark Mode changed slightly (capitalisation, shortcut shown). |
| 2026-11-01 | Families (recent files, encodings, charsets, languages) are `Command` variants with an index; `MenuProvider` / `GroupedMenuProvider` in core build their items. Tabs, fold levels, hashes, presets, browsers, search engines and project slots still use id ranges. | Standing decision 4: the named families were converted; the rest have no state-dependent content and can follow the same pattern later. |
| 2026-11-01 | `KeyMap` resolves conflicts: a command on its default keeps it; between overrides the lower id wins; the loser keeps its default. Reported at start-up (trace and status line) and when the mapper is saved. | User instruction. |
| 2026-11-01 | The theme gained colors, spacing, radius, font and scale (see ui-kit/src/theme.rs). Extra tokens beyond the plan: input, bg_active, disabled, ink, accent_line, info, badge. | Existing components needed them; leaving them as literals would break the no-hard-coded-colours rule. |
| 2026-11-01 | tests/design_tokens.rs fails the build when a colour triple, hex colour string or font name appears outside theme.rs and native/. Component layout constants (heights, widths) stay as named constants in their component. | Enforces the rule; pixel metrics of a component are its own design, not shared spacing. |
| 2026-11-01 | ui-kit/src/components/ holds one component per file; the old controls.rs is split into 11 files sharing the internal themed! macro. ui_kit::controls and the old module paths are re-exported. | Phase 4 component rules. |
| 2026-11-01 | The gallery's WebPane renders blank in PrintWindow captures (WebView2 draws on its own surface). | Screenshot limitation only. |

- Allowed `clippy::wildcard_imports` workspace-wide: child modules split out of a large file use `use super::*;` to share the parent's items.
- Replaced the operating system's popup menus with `ui_kit::popup_menu` (themed, non-activating, mouse-capturing). Reason: on Windows 10.0.26300 the native dark popup renders light items on a dark gutter in every preferred-app mode, so theme tokens could not reach it. Removed `native::set_app_dark` and the TrackPopupMenu loop.
- One Settings window (`ui_kit::settings_window`) replaces the Preferences dialog: category navigation is a vertical `TabStrip`, rows apply instantly and are saved, with no OK button. Style Configurator, Shortcut Mapper, the right-click menu editor and Encryption keep their own editors, opened from a button on their page; their Settings-menu entries open the window on that page.
- Settings window editors are inline: `form::embed` builds an existing declarative form into a page (`Control::Custom`) instead of a dialog; the shortcut mapper, right-click menu editor and colour editor apply on every change, and encryption actions are page buttons that rebuild the pages. The modal versions were removed.
- Settings polish (unslop audit): no accent bar per row (accent only on the active nav item), descriptions in the muted text colour and dropped when the title says it, 4px-step spacing, text boxes and form lists drop the system border, list headers use the DarkMode_ItemsView theme. Keycap shortcuts need an owner-drawn list and are not done.
- Release size: wx release profile is opt-level s, fat LTO, one codegen unit, stripped (panic stays unwind: wxdragon catches UI-callback panics). wxdragon default features are off (no TIFF/JPEG/XPM/Tango/printing/appindicator; printing uses the web view). Result 25.5 MB vs 53.7 MB before; delivered 2.0.1 was 23.6 MB.
- Language auto-detect: text pasted (a jump of 12+ characters) into an untitled tab that is still Normal text gets a language from core::detect (structured formats first, then token scores; no guess when unsure). Choosing a language by hand locks the tab.
- 2.0.2 release: the wx shell is what ships. Windows is supported; macOS (arm64) and Linux (x64) are built by CI as experimental and attached to the release only if they build (continue-on-error). The in-app updater is Windows-only; elsewhere Check for Updates opens the releases page. Asset setup is scripts/setup-assets.js (Node, all OSes); the old Scintilla/Lexilla build script was removed (the wx build bundles them).
- Scroll position is stored and restored as a document line (Workspace::top_doc_line / set_top_doc_line), never as a display line: with word wrap, a display line restored right after a document swap (autosave, tab switch, reload) lands on a later document line. Each 10 s autosave used to move a wrapped document further down.
- Auto-update (Windows, installed release only: not debug builds, test instances or other systems): background check 10 s after start and every 6 h when Settings > Update automatically is on; a found update downloads at once and is installed at the next start, before any window exists (the new version restarts with the same files to open). One try per version (apply-attempt.txt), so a failed install cannot restart-loop. Background failures are quiet (status bar); only user-asked ones show a dialog.
- Tab tool tips: resting on a tab that is not the active one shows its name, folder and the first 12 lines (90 characters each) of its text; read by briefly swapping the tab's document into the view and restoring selection and scroll (Workspace::tab_preview). The active tab has no tip (its text is on screen); whiteboards show their element count.
- Native message boxes and pickers are built only in `ui_kit::ask` (tell, yes_no, yes_no_cancel, open_files, save_file, folder, choice, colour_of, font); `check-architecture.sh` fails on a dialog builder anywhere else. The themed message dialog replaces `ask`'s inside, not its callers.
- Dialog state lives in its form (`Form::set_state` / `with_state` / `take_state`), not in `thread_local!` statics: form callbacks are plain `fn` pointers, so the form carries what they need. Worker threads hand results through an `Arc<Mutex<_>>` slot the app owns. Globals kept on purpose are listed in audit.md, Deliberate global state.
- Messages and questions use the themed `ui_kit::message_box` (icon, wrapped text, buttons right-aligned with the primary rightmost: OK; No, Yes; Cancel, No, Yes). Enter presses the default, Esc the cancelling one. It is laid out explicitly with one label per line: in the dark theme a native static paints only its first line, and a sizer layout left the text unpainted.
- Error notices from the workspace (`Ui::error`) and the manual update check's result are toasts (`ui_kit::toast::Toaster`, owned by `WxUi`), not message boxes; before the frame is shown they stay message boxes. Toasts float on the frame, do not follow it when it moves, and stack up to three.
- DPI: system-aware (app.manifest) rather than per-monitor: one scale for the process, taken at start (`theme::init_display_scale`), since every metric reads `Theme::px` and nothing could re-lay out on a monitor change. Pure layouts stay at 1000nits with tests (find panel, form specs); they are scaled when placed. Core gets the scale as a percentage (`Workspace::set_ui_percent`) for margin widths. `NOTEPP_UI_SCALE` is a test hook, not a setting.
- Screen readers: each custom-painted bar publishes its items while painting (`ui_kit::a11y::Items`); a press from a reader runs on a one-shot timer, since it can open a dialog. Debug builds use the GUI subsystem like release, so running the app never opens a console window; stderr can still be redirected.
- The preview page reports a scroll to the editor only while the user is scrolling it (wheel, keys, touch, or a mouse press, plus 500 ms): renders and images loading also scroll the page and used to pull the editor away from the caret. Clicking a tab gives the keyboard to the tab's content, like Ctrl+Tab.
- Docked tab: one at a time, in a second view that swaps with the current one, so no command needed changing. Docking another replaces it; Dock acts on the current tab, and the tab menu makes the clicked tab current first. The main view never shows the docked tab: a tab closing there falls to its neighbour. Left and Top put the dock first. The preview keeps its own pane to the right of both. The badge on a tab is as wide as its text (`dock` needs more than the old 24 px).
- Splitter sashes are painted from the theme (`theme::own_sash`): the toolkit uses a system colour, a light bar in the dark theme. The handler must not skip the paint event, and a resize asks for a paint just after it, because the toolkit also draws the sash directly when it lays out.
- Keyboard in the bars: F6 and Shift+F6 (registry commands, so rebindable), since Tab must type in the editor. The menu bar is left out: F10 and Alt reach it. `ui_kit::keynav` walks the items a bar publishes for screen readers, so bars share one implementation. Bars have wxWANTS_CHARS so arrows and Tab reach them, so a bar handles them itself.
- Preview blocks: tables, code blocks and Mermaid diagrams get a hover toolbar (Copy; diagrams also zoom out/in/Fit, Copy image, Copy source; Ctrl+wheel and drag-to-pan on a diagram). Page zoom scales each pane (`#body > *`) rather than the scrolling box, and wide tables and diagrams scroll sideways. The page is not a secure context, so it has no clipboard API: text copies through a hidden textarea, and a diagram goes to the app as raw RGBA pixels (`copy-image:w:h:base64`) which the app puts on the clipboard as a bitmap.
- Markdown preview: GitHub alerts (`> [!NOTE]` and the four others) come from the parser's GFM option and are styled in the page; every heading gets a GitHub-style id (`Headings` in core's preview.rs, `-1`/`-2` for repeats; heading attributes stay off, so braces are never turned into attributes) and the page scrolls to it when an in-page link is clicked.
- Preview libraries: highlight.js 11.12 (common languages, browser build, `assets/highlight.min.js`, 129 KB) colours fenced code with a language tag, and KaTeX 0.19 (`assets/katex.min.js`, 273 KB) typesets `\$..\$` and `\$\$..\$\$` (parsed by pulldown-cmark's math option) as MathML, which the system WebView draws itself, so no fonts or stylesheet are shipped. Both load on first use like Mermaid (`need-highlight` / `need-katex`); the colours are our own tokens in preview.html, light and dark. Blocks without a language stay plain; code over 60 000 characters is not coloured.
- Picture tabs (`TabKind::Image`): Ctrl+V with only a picture on the clipboard (text wins) or opening a .png/.jpg/.gif/.bmp/.webp file opens a tab whose `content` is the file's bytes as base64, shown by `assets/imageeditor.html` in its own web view (a plain canvas editor: crop, rotate, flip, resize, pen, highlighter, arrow, rectangle, ellipse, text, pixelate, undo/redo, copy, save), so no new dependency; no ready-made Rust editor can be embedded in this shell (Satty/Swappy are Wayland-only apps, PaintFE is an egui app). The page decodes, edits and sends back a PNG (`state:<edited>:<base64>`); Rust only holds, saves and puts it on the clipboard. Pictures are always saved as PNG (a chosen .jpg becomes .png); a non-PNG file opens as an unsaved picture so Save never writes PNG bytes into a .jpg. A pasted picture reaches the page as raw RGBA, since the page has no clipboard access. `is_page()` means whiteboard or picture (no Scintilla view); `is_whiteboard()`/`is_image()` are for what only one of them needs.
- Picture editor layout follows the common screenshot editors: a left icon bar (Select, Rectangle, Ellipse, Line, Arrow, Freehand, Text, Speech bubble, Step label, Highlight, Hide/pixelate, then Crop, Rotate left/right, Flip horizontal/vertical, Resize), a top row of Save, Copy, Undo, Redo, Delete and zoom, and a properties row (fill, line colour, thickness, text size). Annotations are objects until the picture is saved, copied, cropped, rotated, flipped or resized: they can be selected, moved, resized by handles, restyled and deleted (double-click edits text), and those picture-wide operations flatten them into the picture first. After drawing one, the tool returns to Select. The page sends the app the flattened PNG, never the objects.
- Picture canvas: with the Select tool and nothing selected, eight dots sit on the picture's border; dragging one grows or shrinks the canvas from that side (new area is white, shrinking crops, annotation objects keep their place on the picture). It is undoable and shows the new size while dragging. This is a canvas resize, not a scale: Resize in the left bar scales the pixels.
- Moving the picture on a bigger canvas: the editor remembers where the original picture sits (`photo`) through canvas resizes. The Centre button puts it in the middle, and dragging the background with Select (nothing selected) moves it; annotation objects move with it, so they stay in place on the picture, and the exposed area is white. Crop, rotate, flip and Resize flatten and reset it to the whole canvas.
- Tab and Shift+Tab are not shortcuts of the Indent commands, for the same reason as Del: a plain editing key stays with the focused control. The editor types at the caret and indents a multi-line selection itself. Do not bind plain editing keys as menu shortcuts.
- Del is not a shortcut of Edit > Delete: the key stays with the focused control (the editor handles it natively, the Find box edits its own text). The menu shows `Delete key` as a hint, which is not a parsable chord, so it makes no accelerator.
- The update signature covers `Note++ update <version>` plus the digest file, not the digest alone: an old genuine build served under a higher tag would otherwise pass. The private key was generated locally and is not in the repository.
- The update download addresses must start with this repository's release path, on top of the signature.
- `ring` is a direct dependency of core only for checking update signatures; it was already in the build through ureq's TLS.
- Links in the preview open in the system browser on a single click, without a confirmation, as in any browser. Only http, https and mailto; relative links do nothing, as before.
- Vault consent is per scheme and host for the session and is not saved: agreeing for https does not cover http.
- The Recycle Bin keeps going through PowerShell with the path as data, and now runs without a console window.
- The release ships Microsoft's WebView2Loader.dll beside the exe. `Scintilla.dll`, left by older builds, is deleted by the installer and the updater: the exe has Scintilla built in.
- The clean-start check in `package.ps1` runs only on a build server: run locally it would open a window.
- The preview divider's position is one share for all tabs, kept while the program runs and not saved: a tab has no width of its own, and moving it in one tab moves it in the next.
- Floating tabs: every kind of tab floats and docks, and one tab always stays in the strip (a text tab, beside a dock). A floating tab loses its pin, since it comes back last and pinned tabs come first. Each floating whiteboard or picture is a WebView2 page of its own, as the user chose over a native whiteboard (2026-11-05).
- Close All and the other "close many" commands are about the strip: a floating window is closed by the user, one at a time.
- Ctrl+Tab does nothing in a floating window: the other tabs are in the main window.
- The tab menu's old Undock is now Dock Back, for docked and floating tabs alike; Undock now means "make it a window".
- Floating windows have no parent window, so that they minimise and appear on the taskbar on their own.
- One whiteboard page and one picture page serve the dock, each kept once made: a dock holds one tab, and a page costs a WebView2 start. They stay loaded after Dock Back.
- The whiteboard's source moved from `old-src/src` to `whiteboard/`, as `old-src` is not to be extended; the build and its packages stay there for now.
- Only the icons a tree uses are saved in a whiteboard file: all twenty are in every page, and a board with no tree must not grow.
- A tree's connector lines use Excalidraw's dotted style, which is coarser than a classic tree's at this size: finer dots would mean many more shapes per row.
- The Library shows the built-in items under Excalidraw's own heading "Excalidraw Library", which has no setting to change.
- MCP: `tools/list` gives every tool whatever the level: an agent told "ask the user to choose Edit" helps more than one that cannot know the tool exists, and the level can change while it is connected.
- MCP: opening a file and switching tabs are allowed at Read only. They change what is on screen, not any file, and reading a file needs them.
- MCP: Settings offers Read only and Edit. Full comes with the commands it would allow (Stage 2), so that no option does nothing.
- MCP: until the user's approval of new clients exists (Stage 5), encrypted documents are simply refused, and with no workspace folder an agent reaches open tabs only.
- MCP: new documents and opened files come to the front, as they do for the user; working on an existing tab does not move the user.
- MCP: a save refuses a file changed on disk since it was read, and a save to a path refuses any existing file other than the tab's own. Saving a hidden tab activates it for the moment, as Save All does.
- MCP: the copied setup is treated as a password: kept out of the clipboard history and cleared after 30 seconds.
- MCP: the default port is 47811, away from the usual development ports. If something else has it, Settings says so and the port can be changed.
- MCP: connections over the limit of 16 wait in the system's queue. Turning one away unread resets it on Windows, which a client takes for a failure.
